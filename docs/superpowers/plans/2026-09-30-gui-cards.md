# SDR Web GUI Cards Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Space Raiders SDR web GUI into a multi-viewer ground station.
It gets a card-based Telemetry page, server-side presets, per-client channel
fan-out with rate budgets, decoded APEX FLIGHT data, derived events, offline
maps, a 3D trajectory card, and a Tune page updated for the real receiver and
demo data.

**Architecture:** The Python hub decodes each record once. It feeds capped
history and an event deriver, and publishes `Outgoing` objects that are encoded
once: JSON strings, or binary rows for spectrum and flight data. A per-client
`Outbox` applies subscriptions, role rate budgets, latest-wins slots and bounded
streams. The Svelte frontend keeps columnar ring buffers, draws visible cards
from one rAF scheduler, and lays cards out on a 12-column snapping grid defined
by server-stored presets.

**Tech Stack:**
- Python 3.9+ (stdlib, plus aiohttp in the `gui` extra) with unittest.
- Svelte 5, Vite and TypeScript, tested with Vitest (node environment) and
  svelte-check.
- New runtime frontend dependencies: leaflet, uplot and three. New dev
  dependencies: @types/leaflet and @types/three.

**Spec:** `docs/superpowers/specs/2026-09-30-gui-cards-design.md`. Read it before
any task. Section references (§n) below point into it.

## Global Constraints

- Python supports 3.9+: no `match`, no `X | Y` type unions at runtime, no
  `dict | dict`. RTL is not touched.
- Logic lives in toolkit-free modules (`apex.py`, `units.py`, `gui_wire.py`,
  `events.py`, `history.py`, `fanout.py`, `presets.py`, `maps.py`, `hub.py`).
  `web/server.py` stays thin aiohttp glue.
- Frequency math stays in Python. The frontend only draws and sends intent.
- Dependencies: runtime frontend adds exactly `leaflet`, `uplot` and `three`.
  Dev-only adds `@types/leaflet` and `@types/three`. Python adds none (use
  `urllib`). There are no CDNs, and everything is bundled by Vite. `three` is
  imported only with dynamic `import()`.
- Display values as decoded. Never correct flight-computer oddities. Only
  malformed frames (bad CRC or length) are rejected from flight channels.
- Every SYNTHETIC-derived display is labelled (§12). Never claim hardware
  verification from simulation or replay.
- Operator-only actions (wire role `admin`, UI label "Operator") are enforced
  server-side (§5).
- Presets are stored in `.sdr/gui/presets/` (ignored); builtins in
  `tools/sdr_cli/presets/`; state in `.sdr/gui/preset_state.json`. Map tiles
  are stored in `.sdr/maps/`.
- Map tiles come only from the USGS National Map endpoints in §13.2, prefetched
  by `./sdr maps fetch`. Browsers never fetch remote tiles. OpenStreetMap tile
  servers are never used.
- A separate agent is editing `scripts/build.tcl`, `tools/sdr_cli/core.py`,
  `cli.py` and `tui.py`. Do not touch `build.tcl`, `core.py` or `tui.py`. The only
  `cli.py` change is Task 18's additive `maps` subparser; rebase onto the
  parallel-build work first.
- Host verification:
  `PYTHONPATH=tools .venv/bin/python -m unittest discover -s tools/tests -v`
  (install the extra once: `.venv/bin/python -m pip install -e '.[gui]'`).
- Frontend verification:
  `(cd tools/sdr_web && npm install && npm test && npm run check && npm run build)`.
  svelte-check must report 0 errors and 0 warnings.
- Vitest stays `environment: 'node'`, so only pure logic in `src/lib/**` is
  tested. Svelte components stay thin over tested helpers.
- Commits: the controller commits after each task's review. The commit step
  names the files and message. Never stage `key.txt`, `command.txt` or anything

## Review Focus

1. **A late viewer joins while the demo loops.** They get the flight so far
   (snapshot), then live rows with no duplicates or reordering. The test is in
   Task 6.
2. **An operator is taken over mid-edit.** The new operator's stale save must not
   silently overwrite: it fails with `preset_conflict`, and the old working copy
   is kept. The test is in Task 8.
3. **A viewer's phone sleeps or the tab is backgrounded for minutes.** The
   server never disconnects it for data. The stream overflows into a resync
   snapshot, while control messages still arrive in order. Tests are in Tasks 5
   and 6.
4. **A preset saved by an older or newer GUI version** (unknown config keys, a
   missing key, an unknown card type, overlapping or off-grid cards) still
   loads: config is sanitized, the grid is repaired, and an unknown type
   renders a placeholder. The test is in Task 10.
5. **Garbage GPS** (the demo's `gps_fix` 0 at 65.7/123.2, `lat = lon = 0`, NaN)
   is never plotted as a position, and hostile `/tiles` paths (`..`, negative or
   huge zoom, an unknown layer) return 400 or 404 without reading outside
   `.sdr/maps`. Tests are in Task 19.

### Task 5: Per-client outbox, channels and rate budgets

**Files:**
- Create: `tools/sdr_cli/fanout.py`
- Test: `tools/tests/test_fanout.py`

**Interfaces:**
- Produces:
  - `CHANNELS = ('flight', 'flight.A', 'flight.B', 'events', 'link', 'frames', 'spectrum.A', 'spectrum.B', 'iq.A', 'iq.B')`
  - `@dataclass(frozen=True) class Outgoing: channel: str; mode: str; key: str; data: object`.
    `mode` is 'stream', 'slot' or 'control'. `data` is `str` or `bytes`.
    `channel` is '' for control and 'stats' for stats.
  - `ROLE_BUDGETS = {'admin': {...}, 'viewer': {...}}`, the minimum intervals
    in seconds per channel name plus `'stats'`, exactly per §2.4.
  - `STREAM_MAX = {'admin': 2000, 'viewer': 600}`, `CONTROL_MAX = 400`
  - `class Outbox(role='viewer', clock=time.monotonic)` with:
    - `set_role(role)`;
    - `subscribe(channels) -> set` of newly added channels (raises
      `ValueError` naming unknown channels, leaving the state unchanged);
    - `subscribed -> frozenset`;
    - `offer(out)`, which ignores unsubscribed data channels (control and
      stats always pass);
    - `control(data)`;
    - `put_snapshot(channel, items)`, which appends all items to the stream in
      one step, bypassing budgets;
    - `next() -> tuple` of `(data | None, wait_s | None)`. `data` is the next
      item to send. When nothing is due, `wait_s` is the seconds until the
      earliest due slot (None if nothing is pending);
    - `take_resync() -> set`;
    - `take_dropped() -> dict`;
    - `overflowed: bool`, set when the control queue exceeds `CONTROL_MAX`;
    - `on_ready`: an optional zero-argument callback invoked whenever an item
      becomes available.

- [ ] **Step 1: Write the failing tests** with a fake clock (`now = [0.0]`,

    Each delivered row is the latest offered at that moment, never an older one.
