# Host link layer design

Status: approved 2026-09-29. Scope: the first stage upstream of `uart_tx`, as shown in
[the module map](../../sdr_pipeline.drawio). The upstream receiver stages do not exist yet.
Their messages come from stand-in producers that set a `SYNTHETIC` flag.

## Goal

Every receiver output crosses one FPGA-to-host UART link as typed, delimited,
CRC-checked messages:

- combined telemetry
- per-channel frames and metrics
- link statistics
- spectrum rows
- I/Q snapshots
- status

The host `sdr` CLI and dashboard decode and display all of them. When this stage
is done, the board transmits every message type with fake data, and
`./sdr receive` shows them decoded.

Out of scope: host-to-FPGA commands (UART RX), the real DSP stages, the GUI, and
persistent flash.

## Physical link

- 8N1 at **1 000 000 baud**. `uart_tx` stays unchanged: 100 MHz / 1 Mbaud is
  exactly 100 clocks per bit.
- The theoretical payload ceiling is 100 kB/s. The fake traffic below averages
  about 12 kB/s.
- The host default baud becomes 1 000 000. A local `.sdr/config.json` that pins
  115200 must be updated with `./sdr setup --baud 1000000`.

## Framing

A message is encoded as `COBS(header ‖ payload ‖ crc) ‖ 0x00`.

| Offset | Field | Type | Notes |
| --- | --- | --- | --- |
| 0 | `type` | u8 | message type (see table below) |
| 1 | `flags` | u8 | bit 0 `SYNTHETIC`, bit 1 `EMPTY`, bits 2–7 reserved (0) |
| 2 | `seq` | u8 | link-wide message counter, wraps at 256 |
| 3 | `len` | u16 LE | payload length, 0–512 |
| 5 | payload | `len` bytes | per type, little-endian fields |
| 5+len | `crc` | u16 LE | CRC-16-CCITT over bytes 0 … 4+len |

**CRC:** poly 0x1021, init 0xFFFF, no reflection, no final XOR. This is the same
algorithm as the APEX radio frames; the check value for `"123456789"` is 0x29B1.

**COBS**, both encoder and decoder:

- Each block has a code byte `n` (1–255) followed by `n−1` nonzero data bytes.
- A code below 255 implies a zero after its block, unless the input ends there.
- After 254 nonzero bytes the encoder writes code 0xFF and starts a new block.
- If the input ends exactly after a 0xFF block, the encoder emits a final `0x01`.
- The RTL and Python encoders implement this identical algorithm, so their
  output matches byte for byte.
- The decoder accepts any valid COBS.

**Host resync:** discard bytes up to and including the next `0x00`. A message is
rejected, and counted, if its COBS is invalid, it is shorter than 7 bytes, `len`
disagrees with its size, or the CRC fails. The host counts `seq` gaps as lost
messages.

`SYNTHETIC` means the payload was generated by a stand-in, not measured. The
host labels such records **SIMULATED** everywhere. `EMPTY` means the producer
exists but has no data. Neither flag is set once a real stage replaces its
stand-in.

## Message types

Channel values: 0 = A, 1 = B. `t_us` is a u32 free-running microsecond
timestamp that wraps. `raw` is an APEX radio frame exactly as received after the
sync word: type, body, then CRC-16 **big-endian**, as in `fsw/src/radio.cpp`.

| Type | Name | Payload | Len |
| --- | --- | --- | --- |
| 0x01 | STATUS | `version u8 (=1)`, `channels u8 (bitmask, 0b11)`, `uptime_ms u32`, `build_id u32`, `dropped u16` | 12 |
| 0x10 | BEST_TELEM | `t_us u32`, `source u8`, `frame_len u8`, `raw[frame_len]` | 6+n |
| 0x11 | CHAN_FRAME | `channel u8`, `crc_ok u8`, `t_us u32`, `rssi_dbm_x10 i16`, `quality u8 (/255)`, `freq_offset_hz i32`, `frame_len u8`, `raw[frame_len]` | 14+n |
| 0x20 | CHAN_METRICS | `channel u8`, `rsvd u8`, `rssi_dbm_x10 i16`, `noise_dbm_x10 i16`, `snr_db_x10 i16`, `freq_offset_hz i32`, `sync_hits u32`, `crc_good u32`, `crc_bad u32` | 24 |
| 0x21 | LINK_STATS | `from_a u32`, `from_b u32`, `both_ok u32`, `neither_ok u32`, `best_sent u32` | 20 |
| 0x30 | SPECTRUM | `channel u8`, `rsvd u8`, `row u16`, `bins u16`, `power u8[bins]` (0.5 dB/LSB above floor) | 6+bins |
| 0x31 | IQ_SNAPSHOT | `channel u8`, `rsvd u8`, `pairs u16`, `(i i16, q i16)[pairs]` | 4+4·pairs |

Additional notes:

- **STATUS `dropped`:** messages that producers discarded because the link had
  not accepted their previous message before the next one was due.
- **BEST_TELEM `source`:** 0 = A, 1 = B, 2 = combined (reserved for soft
  combining).
- **`build_id`:** a synthesis parameter, 0 by default.
- **Future types:** the host reports unknown types as `UNKNOWN(0xNN)` without
  failing.

## FPGA architecture (`projects/sdr/rtl/`)

```text
producers ──▶ link_tx (fixed-priority arbiter + header/CRC framer) ──▶ cobs_encoder (message buffer) ──▶ uart_tx
```

**Producer port.** Each port is one message stream. The signals are
`req`, `type[7:0]`, `flags[7:0]`, `len[15:0]`, `grant`, `data[7:0]`, `valid`,
and `ready`.

1. The producer holds `req` and a stable header until the message completes.
2. The arbiter raises `grant` for the whole message.
3. The producer supplies exactly `len` bytes with `valid/ready`, then drops
   `req` after the final accepted byte.
4. Ports are packed as flattened vectors. Port 0 has the highest priority, and
   arbitration happens only between messages. There is no round-robin: under
   overload the low-priority producers drop, and the drops show up in STATUS.

**Modules:**

- **`crc16_ccitt.sv`:** combinational one-byte CRC update.
- **`link_tx.sv`:**
  - latches the winning port and emits `type, flags, seq, len`, the payload
    bytes, then `crc_lo, crc_hi` as a byte stream with `last`;
  - increments `seq` per message.
- **`cobs_encoder.sv`:**
  - encodes one message at a time into a byte buffer (`DEPTH` = 1024), in a
    single pass, by backpatching code bytes;
  - then streams the buffer and a trailing `0x00` to `uart_tx`;
  - stalls input for one cycle when a 254-byte block closes;
  - accepts the next message only after the previous one has been sent. The gap
    this leaves on the wire (about 0.1 byte time) is negligible, so no
    ping-pong buffer is needed.
- **`link_test_sources.sv`:** seven stand-in producers plus a timebase. Base tick
  = `TICK_CYCLES` (default: 10 ms of clock).

  | Order | Producer | Every (ticks) | Content |
  | --- | --- | --- | --- |
  | 0 | BEST_TELEM | 5 | per-slot selection from the A/B frames below; skipped when both fail |
  | 1–2 | CHAN_FRAME A/B | 5 | APEX TEST frame, incrementing seq, CRC computed in RTL. A fails every 11th slot, B every 7th; a failed frame flips the last CRC byte. Fake RSSI/Δf/quality drift slowly. |
  | 3–4 | CHAN_METRICS A/B | 10 | counters consistent with the frames |
  | 5 | LINK_STATS | 100 | |
  | 6 | STATUS | 100 | first one at reset release |
  | 7–8 | SPECTRUM A/B | 10 | 256 bins, noise floor + a tone that walks across bins |
  | 9–10 | IQ_SNAPSHOT A/B | 20 | 64 points on a noisy circle (constant-envelope FSK) |

  Every message sets `SYNTHETIC`. A producer whose previous message is still
  pending when its period elapses drops the new one and increments `dropped`.
- **`sdr_top.sv`:**
  - replaces the `SDR READY` ROM with `link_test_sources → link_tx →
    cobs_encoder → uart_tx` at `BAUD_RATE = 1_000_000`;
  - LED0 toggles each time a STATUS message is sent;
  - `btnC` still resets the design.

## Host architecture (`tools/sdr_cli/`)

- **`protocol.py`:**
  - `crc16_ccitt`, `cobs_encode`, `cobs_decode`, `encode_message`;
  - a dataclass for each message type, and `parse(message) → record`;
  - `StreamDecoder.feed(bytes) → [record]`, with counters: per-type counts,
    CRC, COBS and length errors, resync bytes, `seq` gaps, synthetic count;
  - `LinkState`: the latest record per type and channel, a telemetry ring,
    spectrum row history per channel, the latest I/Q, and per-type rates.
- **`apex.py`:**
  - parses APEX raw frames (TEST, FLIGHT, HK) and checks their CRC;
  - mirrors APEX `radio_gfsk_rx.py`;
  - is provisional until the defined flight-computer format is supplied.
- **`serial_io.Session`:**
  - also feeds a `StreamDecoder` and a `LinkState`;
  - raw text/hex buffers stay as they are;
  - legacy `SDR READY` detection stays.
- **CLI:**
  - `sdr receive --format decoded` becomes the new default, with one line per
    record; SIMULATED records are marked.
  - `--format records` emits JSON lines.
  - The existing `text`, `hex`, `raw` and `json` formats are unchanged.
  - Every receive ends with a per-type summary table and the decoder error
    counts.
- **TUI:**
  - `v` toggles pane 03 between RAW and LINK.
  - LINK shows A/B metrics, recent telemetry, link statistics, a waterfall per
    channel, and a constellation.
  - The traffic pane adds per-type rates and errors.
  - The device pane shows the protocol version and build ID, plus SIMULATED
    while the flag is set.
  - The existing minimum terminal size still works.
- **`projects/sdr/host/check_link.py`:**
  - replaces `check_heartbeat.py`;
  - passes when, within N seconds, it has decoded every message type with zero
    CRC/COBS errors and zero `seq` gaps.

## Verification

- **RTL** (`./sdr sim`):
  - CRC check value and an APEX frame vector;
  - COBS against the golden vector file `projects/sdr/sim/vectors/cobs_golden.hex`
    produced by the Python encoder, covering zeros, 254/255-byte runs, and
    single-byte messages;
  - `link_tx` priority, atomicity, seq, and CRC;
  - a top-level testbench that decodes the UART line, un-COBSes it, checks CRCs,
    and requires every message type plus the LED toggle.
- **Host** (`unittest`): COBS/CRC vectors, resync after garbage and truncation,
  seq gaps, every parser, `LinkState`, CLI decoded output, and a TUI LINK render
  through the pseudo-terminal harness.
- **Hardware:**
  - `./sdr build`, with timing and DRC reports inspected;
  - `./sdr program`;
  - `./sdr receive --seconds 10` shows every type decoded;
  - `check_link.py` passes.
  - Only after the hardware pass does the heartbeat checker get retired, and
    the handoff records the result.
